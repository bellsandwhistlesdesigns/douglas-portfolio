Multi-Room AV Control System

Developed a simulated AV control architecture capable of managing multiple independent rooms.

Version 3.1 models four spaces: a boardroom, huddle space, theatre, and front desk.

Each room maintains its own equipment state, including:

  • Projector and display power
  • Camera operation
  • Microphone mute status
  • Audio volume levels
  • Projection screen position
  • Lighting and door states

A reusable room factory initializes room objects with a consistent state structure, while the device layer provides common methods for updating equipment settings.

Event-Driven Architecture

The control system uses an event-driven architecture to separate simulated physical inputs from application logic.

Button identifiers are mapped to logical events. An event bus dispatches those events to handlers responsible for updating the appropriate room and equipment state.

This design demonstrates separation of responsibilities between user input, event routing, control logic, and state presentation.

Data-Driven Scene Automation

Implemented a reusable scene engine that applies predefined equipment configurations to individual rooms.

Scenes are represented as collections of actions rather than separate, hard-coded control procedures.

  • Presentation Mode: Configures projection, camera, microphone, lighting, and audio.
  • Video Conference Mode: Configures display, camera, microphone, and audio settings.
  • Front Office Mode: Applies settings appropriate for a reception area.
  • Shutdown Mode: Returns controlled equipment to predefined shutdown states.

The scene engine interprets actions such as setting values, toggling states, and adjusting volume.

Operations Dashboard & State Monitoring

Created a console-based operations dashboard that displays the current equipment state of each simulated room.

The dashboard presents projector, display, camera, lighting, door, volume, screen, and microphone status in a structured table.

Event execution triggers dashboard rendering, allowing state changes to be observed during simulation tests.

Simulated TCP Projector Driver

Developed a separate Lua project to explore the architecture of a network-controlled projector driver.

The simulation models a projector connection, command transmission, response handling, and device feedback.

  • Simulated connection and disconnection functions
  • Power on and power off commands
  • Input selection and volume control
  • Mute-state management
  • Parsing of power, input, temperature, and lamp-hour feedback
  • Connection-state checks before executing control commands
  • Console-based status reporting and functional tests

The current implementation simulates command transmission and device responses. It does not establish a live TCP connection to physical projector hardware.
